# Спецификация целевых состояний кабинета продавца

Актуализировано: 04.07.2026.

## Назначение

Документ описывает целевую бизнес-логику состояний магазина, товаров, тарифов и заказов в кабинете продавца. Это спецификация для `Этапа 1` из плана переработки.

Цель — убрать путаницу между техническими флагами и тем, что реально видит продавец.

## Базовое правило

В интерфейсе кабинета нельзя использовать `is_active` как самостоятельный ответ на вопрос «товар виден покупателям».

Нужно разделять:

- `включён продавцом` — продавец хочет показывать товар;
- `прошёл модерацию` — товар разрешён системой;
- `разрешён тарифом` — лимиты и пакет позволяют показывать товар;
- `виден покупателям` — товар реально попадает в публичный каталог, поиск и страницу магазина.

## Целевые вычисляемые поля магазина

Для каждого магазина в кабинете нужно вычислять единый объект состояния.

Минимальные поля:

| Поле | Смысл |
|---|---|
| `has_store` | У пользователя есть магазин |
| `has_active_package` | У магазина есть действующий тариф |
| `package_name` | Название текущего тарифа |
| `package_ends_at` | Дата окончания тарифа или `null` |
| `package_is_lifetime` | Тариф бессрочный |
| `auto_renew_enabled` | Автопродление включено продавцом |
| `auto_renew_possible` | Баланса хватает для автопродления |
| `balance` | Текущий баланс пользователя |
| `active_products_count` | Количество товаров, включённых продавцом |
| `visible_products_count` | Количество товаров, реально видимых покупателям |
| `active_products_limit` | Лимит активных товаров по тарифу |
| `vip_products_count` | Количество активных VIP-товаров |
| `vip_products_limit` | VIP-лимит по тарифу |
| `can_show_website` | Тариф разрешает показывать сайт |
| `can_show_social_links` | Тариф разрешает показывать соцсети |
| `can_accept_orders` | Тариф и настройки разрешают принимать новые заказы |
| `store_status` | Главный статус магазина |
| `primary_blocker` | Главная причина проблемы |
| `blockers` | Все текущие проблемы магазина |
| `primary_action` | Главное действие для продавца |

## Статусы магазина

| Статус | Когда показывать | Текст для продавца | Главное действие |
|---|---|---|---|
| `no_store` | У пользователя нет магазина | `Магазин ещё не создан` | `Создать магазин` |
| `working` | Есть активный тариф и есть видимые товары | `Магазин работает` | `Открыть магазин` |
| `empty` | Есть активный тариф, но нет видимых товаров | `Магазин создан, но покупатели пока не видят товары` | `Добавить товар` |
| `hidden_no_package` | Нет активного тарифа | `Магазин скрыт: нет активного тарифа` | `Выбрать тариф` |
| `needs_attention` | Есть активный тариф, но есть блокеры | `Магазину нужно внимание` | Зависит от главного блокера |
| `package_expiring` | Тариф скоро заканчивается | `Тариф скоро закончится` | `Проверить продление` |

## Приоритет блокеров магазина

Если есть несколько проблем, интерфейс должен показывать их в этом порядке.

1. `no_active_package` — нет активного тарифа.
2. `auto_renew_insufficient_balance` — автопродление включено, но баланса не хватает.
3. `active_limit_exceeded` — активных товаров больше лимита тарифа.
4. `vip_limit_exceeded` — VIP-товаров больше лимита тарифа.
5. `no_visible_products` — нет товаров, видимых покупателям.
6. `products_need_moderation` — есть товары на модерации.
7. `products_need_fixes` — есть товары с замечаниями.
8. `products_without_images` — есть товары без фото.
9. `website_hidden_by_package` — сайт заполнен, но тариф не разрешает показывать.
10. `social_links_hidden_by_package` — соцсети заполнены, но тариф не разрешает показывать.
11. `orders_disabled_by_package` — заказы отключены тарифом.
12. `orders_disabled_by_seller` — продавец сам отключил заказы.

## Тексты и действия блокеров магазина

| Блокер | Текст | Действие |
|---|---|---|
| `no_active_package` | `Товары скрыты от покупателей, потому что нет активного тарифа.` | `Выбрать тариф` |
| `auto_renew_insufficient_balance` | `Тариф скоро закончится, но баланса не хватает для автопродления.` | `Пополнить баланс` или `Выбрать тариф` |
| `active_limit_exceeded` | `Активных товаров больше, чем разрешает текущий тариф.` | `Выбрать товары для показа` |
| `vip_limit_exceeded` | `VIP-товаров больше, чем разрешает текущий тариф.` | `Снять лишние VIP` |
| `no_visible_products` | `Покупатели пока не видят товары магазина.` | `Открыть товары` |
| `products_need_moderation` | `Часть товаров ждёт проверки.` | `Открыть товары на модерации` |
| `products_need_fixes` | `В части товаров нужно исправить замечания.` | `Исправить товары` |
| `products_without_images` | `Некоторые товары нельзя опубликовать без фото.` | `Добавить фото` |
| `website_hidden_by_package` | `Сайт заполнен, но не показывается на текущем тарифе.` | `Сменить тариф` |
| `social_links_hidden_by_package` | `Соцсети заполнены, но не показываются на текущем тарифе.` | `Сменить тариф` |
| `orders_disabled_by_package` | `Новые заказы через сайт недоступны на текущем тарифе.` | `Сменить тариф` |
| `orders_disabled_by_seller` | `Приём заказов выключен в настройках магазина.` | `Включить заказы` |

## Целевые вычисляемые поля товара

Для каждого товара в кабинете нужно вычислять единый объект состояния.

Минимальные поля:

| Поле | Смысл |
|---|---|
| `enabled_by_seller` | Товар включён продавцом |
| `publication_requested` | Продавец хотел отправить товар в публикацию |
| `moderation_status` | Текущий статус модерации |
| `moderation_actual` | Одобрена именно текущая версия товара |
| `has_images` | Есть хотя бы одно фото |
| `has_active_package` | У продавца есть активный тариф |
| `within_active_limit` | Товар помещается в лимит активных товаров |
| `within_vip_limit` | VIP-товар помещается в VIP-лимит |
| `can_be_ordered` | Товар можно заказать через сайт |
| `visible_to_buyers` | Товар реально виден покупателям |
| `product_status` | Главный статус товара |
| `hidden_reason` | Основная причина скрытия |
| `secondary_reasons` | Дополнительные причины |
| `primary_action` | Главное действие продавца |

## Статусы товара

| Статус | Когда показывать | Текст для продавца | Главное действие |
|---|---|---|---|
| `draft` | Черновик, не отправлен на модерацию | `Черновик` | `Отправить на проверку` |
| `queued` | Ждёт проверки | `На проверке` | Нет действия |
| `checking` | Идёт автоматическая проверка | `Проверяется` | Нет действия |
| `manual_review` | Передан администратору | `На ручной проверке` | Нет действия |
| `changes_required` | Модерация требует правки | `Нужно исправить` | `Исправить` |
| `rejected` | Товар отклонён | `Отклонён` | `Редактировать` |
| `approved_hidden` | Одобрен, но выключен продавцом | `Одобрен, но не опубликован` | `Опубликовать` |
| `visible` | Видим покупателям | `Виден покупателям` | `Поднять товар` |
| `hidden_no_package` | Нет активного тарифа | `Скрыт: нет активного тарифа` | `Выбрать тариф` |
| `hidden_active_limit` | Не помещается в лимит активных товаров | `Скрыт: превышен лимит тарифа` | `Выбрать товары для показа` |
| `hidden_vip_limit` | VIP не помещается в лимит | `Скрыт: превышен VIP-лимит` | `Снять VIP` |
| `hidden_no_images` | Нет фото | `Скрыт: нет фото` | `Добавить фото` |
| `hidden_moderation_outdated` | Товар изменён после модерации | `Скрыт: нужна повторная проверка` | `Отправить на проверку` |
| `hidden_not_enabled` | Продавец снял товар с публикации | `Снят с публикации` | `Опубликовать` |

## Приоритет причин скрытия товара

Если товар не виден покупателям, причина должна выбираться в этом порядке.

1. `moderation_not_approved` — товар не прошёл модерацию.
2. `moderation_outdated` — одобрена старая версия, текущая требует проверки.
3. `not_enabled_by_seller` — продавец сам снял товар с публикации.
4. `no_images` — нет фото.
5. `no_active_package` — нет активного тарифа.
6. `active_limit_exceeded` — товар не помещается в лимит активных товаров.
7. `vip_limit_exceeded` — VIP-товар не помещается в VIP-лимит.
8. `regional_mismatch` — товар относится к другому региону.

Такой порядок нужен, чтобы продавец сначала исправлял то, что находится внутри товара, а потом тарифные ограничения.

## Главное правило видимости товара

Товар виден покупателям только если одновременно выполнено:

1. Продавец включил товар.
2. У товара есть фото.
3. Текущая версия товара одобрена модерацией.
4. У продавца есть активный тариф.
5. Товар помещается в лимит активных товаров.
6. Если товар VIP, он помещается в VIP-лимит.
7. Товар относится к текущему региональному контексту.

Если хотя бы одно условие не выполнено, товар должен остаться в кабинете и получить понятную причину скрытия.

## Список товаров в кабинете

В списке товаров нужно показывать не только название и цену, а статус доступности.

Обязательные элементы карточки или строки:

- название товара;
- фото или аккуратная заглушка;
- цена;
- статус товара;
- причина скрытия, если товар не виден;
- бейдж VIP, если товар VIP;
- дата последнего изменения или отправки на проверку;
- главное действие.

Обязательные фильтры:

- `Все`;
- `Видны покупателям`;
- `Скрыты`;
- `Черновики`;
- `На проверке`;
- `Нужно исправить`;
- `Без фото`;
- `Скрыты из-за тарифа`;
- `VIP`.

## Страница товара в кабинете

На странице товара первым блоком показывать состояние.

Структура блока:

1. Главный статус.
2. Короткое объяснение.
3. Что мешает показу.
4. Главное действие.
5. Дополнительные действия.

Примеры:

- `Товар виден покупателям. Его можно поднять в каталоге.`
- `Товар одобрен, но снят с публикации. Нажмите «Опубликовать», чтобы покупатели увидели его.`
- `Товар скрыт, потому что тариф закончился. Выберите тариф, чтобы вернуть товары в каталог.`
- `Товар изменён после модерации. Отправьте его на повторную проверку.`

## Тарифы

Для каждого тарифа нужно вычислять совместимость с текущим магазином.

Поля совместимости:

| Поле | Смысл |
|---|---|
| `is_current` | Это текущий тариф |
| `can_purchase_now` | Можно подключить без подготовки |
| `has_enough_balance` | Баланса хватает |
| `active_products_fit` | Активные товары помещаются в лимит |
| `vip_products_fit` | VIP-товары помещаются в лимит |
| `will_disable_website` | Сайт перестанет показываться |
| `will_disable_social_links` | Соцсети перестанут показываться |
| `will_disable_orders` | Новые заказы через сайт станут недоступны |
| `required_active_deactivations` | Сколько активных товаров нужно снять |
| `required_vip_deactivations` | Сколько VIP нужно снять |
| `compatibility_status` | Итоговая совместимость |

Статусы совместимости тарифа:

| Статус | Когда показывать | Кнопка |
|---|---|---|
| `current` | Текущий тариф | `Текущий тариф` |
| `available` | Можно подключить сейчас | `Подключить` |
| `insufficient_balance` | Не хватает баланса | `Пополнить баланс` |
| `needs_preparation` | Нужно отключить товары или VIP | `Подготовить переход` |
| `feature_downgrade` | Функции будут недоступны, но лимиты подходят | `Показать последствия` |

## Переход на другой тариф

Если тариф не подходит по лимитам, нельзя просто показывать ошибку.

Нужен сценарий подготовки перехода:

1. Показать текущий тариф и целевой тариф.
2. Показать текущие активные товары и новый лимит.
3. Показать текущие VIP-товары и новый VIP-лимит.
4. Дать выбрать товары, которые останутся активными.
5. Дать выбрать VIP-товары, которые сохранят VIP.
6. Показать функции, которые перестанут работать.
7. Попросить подтверждение.
8. Применить изменения одной транзакцией.

Запрещено:

- удалять товары при переходе;
- молча снимать VIP;
- молча отключать активные товары;
- брать оплату до объяснения последствий.

## Сайт, соцсети и заказы

Настройки магазина должны показывать три уровня состояния:

1. Данные заполнены.
2. Данные доступны по тарифу.
3. Данные показываются покупателям.

Примеры:

| Ситуация | Текст |
|---|---|
| Сайт заполнен, но тариф не разрешает сайт | `Сайт сохранён, но не показывается на текущем тарифе.` |
| Соцсети заполнены, но тариф не разрешает соцсети | `Соцсети сохранены, но не показываются на текущем тарифе.` |
| Заказы включены, но тариф не разрешает заказы | `Новые заказы через сайт недоступны на текущем тарифе.` |
| Продавец сам выключил заказы | `Приём заказов выключен в настройках магазина.` |

## Заказы

Заказы нужно отделить от корзины.

Правила:

- это список заказов, а не корзина;
- старые заказы не скрываются при смене тарифа;
- старые заказы не скрываются при окончании тарифа;
- недоступность новых заказов не влияет на историю заказов;
- покупатель может удалить заказ из своего списка;
- покупатель может очистить список заказов;
- продавец видит историю заказов своего магазина независимо от текущего тарифа.

Статус заказов магазина:

| Статус | Когда показывать | Текст |
|---|---|---|
| `orders_enabled` | Заказы доступны по тарифу и включены продавцом | `Магазин принимает заказы через сайт.` |
| `orders_disabled_by_seller` | Продавец выключил заказы | `Приём заказов выключен в настройках магазина.` |
| `orders_disabled_by_package` | Тариф не разрешает заказы | `Новые заказы через сайт недоступны на текущем тарифе.` |
| `orders_history_only` | Новые заказы недоступны, но история есть | `История заказов сохранена. Новые заказы сейчас недоступны.` |

## Журнал событий

Журнал нужен, чтобы продавец и поддержка понимали, почему состояние изменилось.

Минимальные события:

- магазин создан;
- тариф подключён;
- тариф продлён;
- тариф истёк;
- автопродление не прошло;
- товар создан;
- товар отправлен на модерацию;
- товар одобрен;
- товар отклонён;
- товар скрыт из-за тарифа;
- товар снят с публикации продавцом;
- товар опубликован;
- VIP снят;
- заказы отключены тарифом;
- заказы включены продавцом;
- заказ создан;
- статус заказа изменён.

Каждая запись должна содержать:

- дату;
- тип события;
- короткое описание;
- причину;
- ссылку на объект, если она есть.

## Минимальный технический контракт сервисов

Чтобы не размазывать логику по Blade и контроллерам, состояния должны считаться в сервисах.

Рекомендуемые сервисы:

- `SellerCabinetStateService` — состояние магазина;
- `ProductCabinetStateService` — состояние товара;
- `PackageCompatibilityService` — совместимость тарифов;
- `SellerCabinetActionPresenter` — тексты и кнопки для состояния.

Рекомендуемый подход:

- модели остаются источником данных;
- сервисы вычисляют бизнес-состояние;
- Blade получает уже готовые статусы, причины и действия;
- публичная выдача продолжает использовать строгую фактическую видимость;
- кабинет объясняет, почему фактическая видимость такая.

## Acceptance criteria

Спецификация считается реализованной, когда:

- в кабинете нет места, где `is_active` называется «виден покупателям» без дополнительных проверок;
- список товаров показывает причину скрытия каждого невидимого товара;
- главная кабинета показывает состояние магазина и главную проблему;
- страница тарифов показывает совместимость до покупки;
- переход на меньший тариф не заканчивается тупиковой ошибкой;
- старые заказы видны независимо от тарифа;
- сайт, соцсети и заказы объясняют ограничения тарифа;
- все основные состояния имеют конкретное действие для продавца.
