# Архив: первоначальные требования к MVP-заказам

MVP: оформление заказа на сайте
1. Цель
Добавить на сайт возможность оформить заказ на отдельный товар через кнопку «Заказать».
Заказ оформляется без регистрации пользователя. Онлайн-оплаты на сайте нет. Все расчёты между покупателем и продавцом происходят вне сайта.
2. Основная логика
Так как товары могут принадлежать разным продавцам, а условия доставки у продавцов и товаров могут отличаться, заказ оформляется на каждый товар отдельно.
Корзина в MVP не используется.
На странице товара отображается кнопка «Заказать», если:
•	продавец включил возможность заказов через сайт;
•	товар доступен для заказа.
Если продавец отключил заказы через сайт, кнопка «Заказать» не отображается.
3. Форма заказа
После нажатия кнопки «Заказать» открывается форма заказа.
Поля формы:
•	имя — обязательно;
•	телефон — обязательно;
•	количество товара — обязательно;
•	способ получения:
o	доставка;
o	самовывоз;
•	адрес — обязательный только при выборе доставки;
•	комментарий к заказу — необязательно;
•	согласие на обработку персональных данных — обязательно.
Email не требуется.
4. Логика доставки
Продавец в своём кабинете может указать:
•	есть ли у него доставка;
•	включена ли возможность заказов через сайт;
•	текст с условиями доставки.
Пример текста:
Доставка по Тирасполю — 20 руб., по Бендерам — 50 руб.
Этот текст показывается пользователю перед полем адреса, если выбран вариант доставки.
Продавец может включить доставку:
•	для всех своих товаров;
•	только для отдельных товаров.
Если доставка для товара недоступна, пользователь может выбрать только самовывоз.
Если доставка доступна, пользователь может выбрать доставку или самовывоз.
5. Стоимость
Онлайн-оплаты на сайте нет.
Итоговая стоимость заказа на сайте не рассчитывается.
На форме заказа или странице подтверждения нужно показать текст:
Стоимость товара указана без учёта доставки. Условия и стоимость доставки уточняются у продавца.
Если продавец указал свои условия доставки, они показываются отдельно.
6. Успешное оформление заказа
После отправки формы пользователь попадает на страницу успешного оформления заказа.
На странице отображается:
•	сообщение об успешном оформлении;
•	номер заказа;
•	название товара;
•	количество;
•	имя покупателя;
•	телефон;
•	выбранный способ получения;
•	адрес, если выбрана доставка;
•	комментарий, если он был указан;
•	информация о том, что продавец свяжется с покупателем.
Текст:
Заказ успешно оформлен. Продавец свяжется с вами для подтверждения деталей.
Также должна быть возможность сохранить документ с заказом.
В MVP это может быть:
•	кнопка «Распечатать»;
•	сохранение страницы как PDF через браузер;
•	отдельная кнопка «Скачать заказ», если это не усложняет разработку.
7. История заказов без регистрации
Пользователь не обязан регистрироваться.
При следующем заходе на сайт желательно показать пользователю его ранее оформленные заказы.
Для MVP можно реализовать это через сохранение заказов в браузере пользователя: cookie или localStorage.
Важно:
•	если пользователь зайдёт с того же устройства и браузера, он увидит свои заказы;
•	если пользователь очистит браузер, сменит устройство или откроет сайт в другом браузере, история может быть недоступна;
•	для доступа к конкретному заказу можно использовать уникальную ссылку с токеном.
8. Кабинет продавца
Продавец видит в своём кабинете список заказов только по своим товарам.
В списке заказов отображается:
•	номер заказа;
•	дата создания;
•	товар;
•	количество;
•	имя покупателя;
•	телефон;
•	способ получения;
•	адрес, если есть доставка;
•	комментарий покупателя;
•	статус заказа.
Продавец может открыть карточку заказа и посмотреть все данные.
9. Уведомления продавца
После оформления заказа продавец получает уведомление:
•	в своём кабинете;
•	в Telegram, если продавец подключил Telegram-уведомления.
Если Telegram не подключён, уведомление приходит только в кабинет.
10. Статусы заказа
Статусы заказа задаёт администратор маркетплейса через админ-панель Filament.
В MVP можно предусмотреть базовые статусы:
•	Новый;
•	Принят;
•	В работе;
•	Готов к самовывозу;
•	Передан в доставку;
•	Выполнен;
•	Отменён.
Администратор маркетплейса может управлять списком статусов.
11. Админка маркетплейса
Администратор маркетплейса должен иметь возможность:
•	видеть все заказы;
•	фильтровать заказы по продавцу;
•	фильтровать заказы по статусу;
•	управлять статусами заказов;
•	просматривать карточку заказа;
•	видеть, включены ли заказы у продавца;
•	видеть, включена ли доставка у продавца.
12. Настройки продавца
В кабинете продавца должны быть настройки:
1.	Включить/выключить заказы через сайт.
2.	Включить/выключить доставку.
3.	Указать текст условий доставки.
4.	Подключить Telegram-уведомления.
5.	Включить или отключить доставку для конкретных товаров.
13. Настройки товара
У товара должны быть настройки:
•	доступен ли товар для заказа через сайт;
•	доступна ли доставка для этого товара.
Если доставка у продавца отключена полностью, настройка доставки у товара не применяется.
14. Что не входит в MVP
В MVP не входит:
•	корзина;
•	заказ нескольких товаров сразу;
•	онлайн-оплата;
•	автоматический расчёт стоимости доставки;
•	выбор времени доставки;
•	email-уведомления;
•	SMS-уведомления;
•	регистрация покупателя;
•	полноценный личный кабинет покупателя;
•	сложная география доставки;
•	автоматическая проверка адреса;
•	интеграция с картами;
•	разделение заказа между несколькими продавцами.
15. Основной пользовательский сценарий
1.	Пользователь открывает страницу товара.
2.	Видит кнопку «Заказать».
3.	Нажимает кнопку.
4.	Заполняет форму:
o	имя;
o	телефон;
o	количество;
o	выбирает доставку или самовывоз;
o	вводит адрес, если выбрана доставка;
o	при желании оставляет комментарий;
o	подтверждает согласие на обработку персональных данных.
5.	Отправляет заказ.
6.	Попадает на страницу успешного оформления.
7.	Получает номер заказа.
8.	Может сохранить или распечатать документ с заказом.
9.	Продавец видит заказ в кабинете.
10.	Если Telegram подключён, продавец получает уведомление в Telegram.
16. MVP-критерии готовности
Функция считается готовой, если:
•	продавец может включить или отключить заказы через сайт;
•	продавец может включить или отключить доставку;
•	продавец может указать текст условий доставки;
•	у товара есть кнопка «Заказать»;
•	пользователь может оформить заказ без регистрации;
•	пользователь может выбрать количество;
•	пользователь может выбрать доставку или самовывоз;
•	адрес требуется только при доставке;
•	заказ сохраняется в системе;
•	пользователю показывается номер заказа;
•	есть страница успешного оформления заказа;
•	продавец видит заказ в кабинете;
•	продавец получает уведомление в кабинете;
•	Telegram-уведомление отправляется, если продавец его подключил;
•	администратор маркетплейса может управлять статусами заказов.
