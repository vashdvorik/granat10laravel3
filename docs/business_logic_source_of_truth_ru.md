# Источники истины бизнес-логики BIMM

Актуализировано: 20.07.2026.

Этот документ фиксирует, какие части проекта считаются источником истины по
каждому домену. Он нужен как основа для рефакторинга: если правило есть в
нескольких местах, в документе указано, где должно жить главное решение, а
какие части являются производными.

## 1. Принцип

Для каждого домена должен быть один главный источник истины.
Остальные классы могут:
- читать это состояние;
- представлять его в UI;
- вычислять производные статусы;
- валидировать ввод;
- выполнять действие.

Но они не должны заново придумывать бизнес-правило.

## 2. Источники истины по доменам

## 2.1 Товар

### Главный источник истины
- `App\Models\Product`
- `App\Enums\ProductModerationStatus`
- `App\Services\ProductStateTransitionService`

### Что они определяют
- текущий статус модерации;
- активирован ли товар;
- можно ли отправить на проверку;
- можно ли публиковать;
- можно ли поднять товар;
- можно ли открыть публичную страницу;
- почему товар скрыт.

### Производные слои
- `App\Services\ProductCabinetStateService`
- `App\Services\ProductViewStateFactory`
- `App\Services\ProductDisplayStateResolver`
- `App\Services\ProductWriteService`

### Что считается источником правды
- для логики переходов — `ProductStateTransitionService`;
- для хранения фактического состояния — `Product`;
- для статуса модерации — `ProductModerationStatus`.

## 2.2 Публичная видимость товара

- `App\Services\ProductCabinetStateService`

## 2.4 VIP-товары и баланс продавца

Тарифов (пакетов) в проекте больше нет. Лимитов на количество товаров нет,
сайт, соцсети и приём заказов не зависят от тарифа (приём заказов включает сам продавец).

### Главный источник истины
- `App\Models\Product` (поля `is_vip`, `vip_until`)
- `App\Services\ProductVipService` — покупка VIP за баланс, снятие по сроку, ручная установка администратором
- `App\Services\VipPricing` — стоимость VIP
- `App\Models\User` (поле `balance`) — денежный баланс продавца

### Правила
- VIP покупается продавцом отдельно для каждого товара на странице товара в кабинете;
- сроки: 1 день, 7 дней, месяц (30 дней), год (365 дней);
- стоимость = цена одного дня × число дней; цену дня задаёт администратор в админке
  («Система → Настройки VIP»), по умолчанию 1 руб за день;
- при покупке деньги списываются с баланса, повторная покупка продлевает срок от даты окончания;
- по окончании срока флаг VIP снимает команда `products:expire-vip` (каждые 5 минут);
- `vip_until = null` при `is_vip = true` — VIP без срока, выдан администратором;
- продавец сам VIP выставить не может, только купить.

## 3. Что является производным, а не главным

Ниже перечислены вещи, которые не должны быть источником истины сами по себе:

- UI-компоненты Blade;
- страницы Filament;
- текстовые бейджи;
- цветовые статусы;
- счётчики в интерфейсе;
- кэш;
- session;
- localStorage;
- вспомогательные presentational services.

Они могут запоминать, показывать и кешировать, но не должны создавать
собственное правило, противоречащее доменному слою.

## 4. Правило при конфликте

Если два слоя говорят разное, приоритет такой:

1. Модель и enum домена.
2. Доменные сервисы переходов и решений.
3. Application/query services.
4. Presenters / view state.
5. UI.
6. Cache/session/localStorage.

Исключение:
- если UI или клиентское хранилище используется как временный список
  пользовательского выбора, оно может быть источником для самого интерфейса,
  но не для доменной истины.

## 5. Термины, которые нужно держать стабильными

- **Товар** — сущность каталога, продаваемая продавцом.
- **Публикация** — фактическая видимость товара покупателю.
- **Модерация** — проверка товара текстом, правилами, AI или администратором.
- **VIP** — платное повышение товара в каталоге и поиске на выбранный срок.
- **Заказ** — оформленная заявка покупателя на конкретный товар.
- **Избранное** — список отложенных товаров в браузере.
- **Регион** — выбранный населённый пункт/локация, влияющий на выдачу.
- **Блокер** — причина, по которой действие недоступно.
- **Следующий шаг** — главное действие, которое должен сделать пользователь.

## 6. Что это даёт для дальнейшего рефакторинга

После фиксации источников истины можно безопасно:
- сжимать дублирующие сервисы;
- убирать лишние статусы;
- упрощать UI кабинета;
- строить единый слой видимости товара;
- делать код понятнее для нейросети и для людей.
