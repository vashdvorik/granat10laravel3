# Описание проекта для переноса на другой стек

## Кратко

Это русскоязычный локальный маркетплейс для товаров и магазинов Приднестровья/ПМР.
Сайт не является платежной системой: он показывает товары, магазины и позволяет покупателю
связаться с продавцом, оформить заявку на товар и сохранить заказы у себя в браузере.

Основная публичная витрина называется `BIMM`, в интерфейсе встречаются формулировки
вроде:
- «Все товары из Приднестровья в одном месте»
- «Где купить? Смотри на BIMM»
- «Оплата продавцу»
- «Маркетплейс ПМР»

## Назначение

Проект решает 4 задачи:
1. Показать каталог товаров с фильтрами, поиском и региональной привязкой.
2. Показать витрины магазинов/продавцов.
3. Дать покупателю быстрый путь к контакту с продавцом и оформлению заявки.
4. Дать продавцу личный кабинет для управления магазином, товарами, тарифами и заказами.

## Технологическая модель

Исходный проект сделан на Laravel 10 с Blade-шаблонами, jQuery и Bootstrap.
При переносе на другую технологию важно сохранить не стек, а поведение:
- серверная генерация страниц;
- SEO-friendly URL;
- пагинация на desktop;
- кнопка «Загрузить еще» на mobile;
- региональная фильтрация контента;
- кабинет продавца и отдельная админка.

### Используемые идеи из текущего проекта
- `MySQL` как основная БД.
- `Laravel Fortify` для регистрации, входа и сброса пароля.
- `Filament` как админ-панель.
- `Laravel Scout + Meilisearch` для поиска.
- `Redis/queue`-подобная архитектура для фоновых задач и модерации.

## Роли

### Гость
- смотрит главную, каталог, магазины, страницы помощи;
- ищет товары;
- открывает карточки товара и продавца;
- может добавить товар в избранное;
- может оформить заявку на товар;
- может смотреть sitemap и SEO-страницы.

### Покупатель
- использует избранное;
- оформляет заказы;
- видит список своих заказов в этом браузере/сессии;
- открывает детали заказа по `public_id` и токену доступа.

### Продавец
- входит в личный кабинет;
- создает магазин;
- редактирует профиль магазина;
- добавляет товары;
- отправляет товар на модерацию;
- управляет заказами;
- подключает Telegram-уведомления;
- смотрит статистику и тарифы;
- может удалить магазин.

### Администратор
- управляет пользователями, продавцами, товарами, категориями, регионами, поселениями, тарифами и заказами;
- смотрит журнал событий;
- настраивает модерацию;
- работает через отдельную админ-панель `/admin` или путь из конфигурации.

### Избранное
Избранное реализовано как клиентский список в `localStorage`.

Особенности:
- сердечки на карточках переключают товары в избранном;
- страница избранного загружает товары по ID через AJAX;
- если избранное пустое, показывается пустое состояние;
- если избранные товары есть, показываются карточки и кнопка «Загрузить еще»;
- есть рекомендованные товары, если избранное пустое.

Публичный список заказов, сохраненных в этом браузере.
Показывает:

- дату;

Также есть:

- очистка списка;
- переход в детальную карточку заказа.

### Карточка заказа

## Региональная модель

Сайт поддерживает региональные URL.

Есть отдельная логика:
- выбор региона/населенного пункта;
- cookie с выбранным поселением;
- региональные маршруты вида `/{location}/...`;
- фильтрация каталога по поселению;
- `canonical` и `robots`;
- SEO-метки для пагинации;
- schema.org JSON-LD для хлебных крошек и товара.

Важно:
- контент может показываться по всему региону или только по выбранному поселению;
- в `reserved slugs` есть системные пути, которые нельзя использовать как региональные URL.

## Визуальный стиль

### Общее впечатление
Визуально сайт похож на крупный локальный marketplace с акцентом на карточки,
широкие hero-блоки и яркие CTA-кнопки.

### Цвета и UI-логика
- основной акцент: градиент от `#b965ed` к `#4ed9ee`;
- много белых карточек с мягкими тенями;
- округленные углы;
- светлый фон;
- продающие бейджи скидок;
- заметные кнопки «Позвонить», «Заказать», «Загрузить еще».

### Шрифты
- публичная часть использует собственный визуальный микс с иконками Font Awesome;
- кабинет продавца использует `Inter`.

### Адаптивность
Нужно сохранить поведение для desktop и mobile:
- на mobile часть блоков перестраивается в 1 колонку;
- каталог и поиск используют кнопку «Загрузить еще»;
- карточки товаров становятся компактными;
- в карточке товара скрываются второстепенные элементы и появляется нижняя fixed-панель;
- в кабинете продавца sidebar можно сворачивать.

## Бизнес-правила

1. Товар видим в каталоге только если:
   - он активен;
   - модерация одобрена;
   - версия модерации актуальна;
   - у продавца есть активный тариф.

2. Заказ на товар доступен только если:
   - товар активен;
   - заказ разрешен у товара;
   - модерация одобрена;
   - тариф магазина поддерживает прием заказов;
   - магазин разрешает заказы;
   - товар и выбранный регион совпадают.

3. Сайт не принимает оплату.
   - Оплата и получение товара согласуются напрямую с продавцом.

4. Избранное хранится в браузере.
   - это не полноценный аккаунтный wishlist;
   - при открытии страницы данные подтягиваются по ID.

5. Показ товаров зависит от тарифа продавца.
   - без активного тарифа магазин и товары не должны считаться публично доступными.

## Админ-панель

Фильтрация доступа включается флагом `FILAMENT_PANEL_ENABLED`.
Путь панели по умолчанию: `/admin`.

В админке есть:
- `UserResource`
- `SellerResource`
- `CategoryResource`
- `RegionResource`
- `SettlementResource`
- `PackageResource`
- `SellerPackageResource`
- `ProductResource`
- `OrderResource`
- страницы:
  - `CategoryTree`
  - `ActivityLog`
  - `ModerationSettings`

Админка нужна для:
- ручной модерации;
- настройки категорий;
- управления географией;
- тарифами;
- просмотром заказов и статусов.

## Что важно повторить на другой технологии

Если переносить проект, то критично сохранить:
1. Иерархию сущностей: регион -> поселение -> магазин -> товар -> заказ.
2. Каталог с деревом категорий.
3. Региональную фильтрацию и SEO URL.
4. Карточку товара как главный продающий экран.
5. Избранное на базе localStorage и AJAX-подгрузки.
6. Заказ без онлайн-оплаты, только передача заявки продавцу.
7. Личный кабинет продавца с тарифами и ограничениями.
8. Админ-панель и модерацию товаров.
9. Адаптивное поведение mobile/desktop.
10. Русский язык интерфейса и локальный контекст ПМР.
